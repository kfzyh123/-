产品需求文档 · PRD v1.0

AuroraOS · 极光操作系统

面向终端用户的多内核窗口化操作系统。具备多内核、多管理、多窗口、多线程、图形桌面、内置浏览器，以及在系统崩溃时自动修复 99% 故障的「超级修复界面」。

产品契约 背景与目标 范围 产品模型 功能需求 共享规则 待定问题

01 产品契约

主要用户终端用户（消费者与专业用户），需要一台开机即用、稳定且能自我修复的窗口化桌面设备。
触发条件用户按下电源开机，期望进入可用的图形桌面；或在运行过程中发生崩溃/启动失败。
核心任务启动到图形桌面 → 在多窗口中运行应用（多线程） → 浏览网络 → 崩溃后自动进入超级修复界面并恢复系统。
完成证据桌面可用；应用以多窗口运行；浏览器能加载网页；崩溃后系统自动修复且 99% 的常见故障无需人工干预即可恢复可启动状态。
共享对象系统镜像、用户配置档案、修复日志（Repair Journal）。
信任边界每个个性内核、每个浏览器标签页均在独立沙箱中运行；破坏性修复操作必须用户确认。

02 背景与目标

观察到的现象：主流桌面操作系统在崩溃、驱动冲突、系统文件损坏或恶意软件侵入后，常需要用户手动进入恢复模式、使用命令行工具或重装系统，造成数据丢失与生产力下降。

受影响用户与时刻：用户在开机失败或运行中蓝屏/卡死后，因缺乏自动修复能力而中断工作。

产品决策：构建一个多内核、多管理、多窗口、多线程的窗口化操作系统，并把"自动修复"作为一等公民——崩溃即进入图形化「超级修复界面」，按确定性流水线自动诊断并修复。

可观察的预期结果：

  • 用户开机即可进入图形桌面，无需手动配置。
  • 单个内核崩溃后系统不整体宕机，由监管内核切换到备用内核继续运行。
  • 系统崩溃后自动进入超级修复界面，≥99% 的常见故障被自动修复，并在完成后直接重启回桌面。
目标说明："99% 自动修复率"是用户明确设定的目标，覆盖范围限定为常见软件类故障（见 FR-07）。硬件物理损坏与用户数据级丢失不在该覆盖率内，系统对此类情况提供数据抢救建议并标记为需人工处理。

04 产品模型与架构总览

AuroraOS 采用"监管微内核 + N 个个性内核"的多内核结构。监管内核负责启动、监管、隔离与故障切换；个性内核承载实际系统服务与应用。资源管理由多个独立管理域协同，策略管理器统一仲裁。其上为合成器与窗口管理器构成的图形栈，再上是桌面环境与内置浏览器。

图 1 · AuroraOS 分层与多内核架构

关键对象

个性内核

承载系统服务与应用的运行内核，运行于独立地址空间，可热备、可热替换。

监管内核

微内核，负责启动、健康监测、隔离与故障切换，并在崩溃时引导进入超级修复界面。

策略管理器

仲裁各资源管理域的配额、优先级与回收策略，单一权威定义。

窗口会话

一个窗口的可持久化状态（位置/大小/所属桌面/恢复点），跨桌面移动。

修复日志

记录修复流水线每步操作的前后状态，支持回滚，落盘到受保护分区。

还原点

在系统性变更前创建的快照，用于修复与回滚。

05 功能需求

本节为文档主体，按模块（Structure A）组织。每条需求给出稳定 ID、触发、处理规则、结果与状态、异常。

FR-01 多内核子系统

目的

运行多个协作内核，实现故障隔离与韧性：单内核崩溃不导致整机宕机，并支持热备与计划内热替换。

组件

  • 监管微内核（Supervisor Kernel）：首个启动，硬件强制隔离。
  • 个性内核（Personality Kernel）×N：承载实际服务与应用，至少 1 主 + 1 备。
  • 受监管 IPC 通道：内核间通信的唯一路径，由监管内核鉴权。

触发

开机：监管内核最先启动，随后按策略拉起个性内核；运行期：内核健康检查超时或主动维护请求。

处理规则

  • 每个个性内核运行于独立地址空间，由监管内核强制隔离。
  • 内核间通信仅经受监管 IPC 通道，未经授权的访问被拒绝并记录。
  • 个性内核发生恐慌时：监管内核将其隔离，把其服务重定向到备用内核，并写入修复日志。
  • 计划内热替换：在维护窗口暂存新内核版本并切换，无需整机重启；切换前自动创建还原点。

状态

状态说明允许转移
Bootstrapping监管内核正在拉起个性内核→ Running / → Halted(失败)
Running正常提供服务→ Degraded / → Maintenance
Degraded主内核已故障切换到备用→ Running / → Maintenance
Maintenance热替换或修复中→ Running / → Halted
Halted不可恢复，进入超级修复界面→ Bootstrapping(修复后)

异常

  • 内核恐慌：隔离 + 故障切换 + 记录；连续切换失败 → 触发 FR-07。
  • IPC 通道失效：降级为单内核模式并告警。
  • 内核版本不匹配：拒绝启动该内核并回退到上一已知良好版本。

FR-02 多管理资源管理

目的

由多个独立资源管理域协同管理 CPU、内存、存储、网络、设备，并通过策略管理器统一仲裁，实现配额、优先级与回收。

资源域

管理域职责关键策略
CPU 调度器线程调度、亲和性、NUMA按优先级 + 老化，防止饥饿
内存管理器分配/回收、换页、压缩按用户/应用配额，超限回收
存储管理器卷、文件系统、配额按卷配额，写入限速
网络管理器接口、路由、防火墙按应用限速与连接数
设备管理器驱动加载、设备枚举驱动签名校验，失败回滚
策略管理器仲裁配额/优先级/回收单一权威定义

触发

内核/应用发起资源请求；管理域间冲突需仲裁。

处理规则

  • 管理平面与执行平面分离：策略下发由策略管理器统一进行。
  • 各管理域通过策略管理器协商，执行配额与优先级；违规时回收资源并记录。
  • 超售由策略管理器按域策略处理（如内存压缩/换页）。

结果与状态

分配结果持久化到资源账本；资源状态：空闲 / 已分配 / 受限 / 回收中。

异常

  • 资源耗尽：按优先级回收低优先级请求，触发告警。
  • 策略冲突：策略管理器以最高优先级策略裁定并记录。

FR-03 多窗口窗口管理器

目的

管理跨虚拟桌面的重叠/平铺窗口，支持窗口吸附、会话持久化与无响应处理。

布局

桌面、任务栏、系统托盘、窗口边框与控件。

触发

应用打开窗口；用户拖拽/吸附/切换桌面/最小化等操作。

处理规则

  • Z 序管理；焦点跟随点击或悬停（可配置）。
  • 默认提供 ≥4 个虚拟桌面，窗口可在桌面间移动。
  • 窗口吸附：左/右半、四角、四分之一；拖到顶部最大化。
  • 窗口会话持久化：位置/大小/所属桌面在注销/重启后恢复（可选）。

状态

状态说明
Normal正常显示
Minimized收入任务栏
Maximized占满工作区
Tiled / Snapped平铺/吸附到边缘或四分之一
Pinned / Hidden置顶 / 跨桌面隐藏

异常

  • 窗口无响应：变灰，提供"强制结束"。
  • 显示器断开：窗口迁移到剩余显示器并保留几何。

FR-04 多线程运行时

目的

提供内核级与用户级线程的调度、同步与死锁处理。

触发

进程/线程创建、同步原语调用。

处理规则

  • 混合 M:N 模型：用户线程多路复用到内核线程。
  • 优先级：0–31 实时段，32+ 普通段；带老化以防饥饿。
  • 线程池、CPU 亲和性、NUMA 感知调度。
  • 同步原语：互斥锁、信号量、条件变量、读写锁、futex。
  • 死锁检测：检测环等待并按策略打破（终止最低代价线程）。

结果与状态

线程公平调度；线程状态：就绪 / 运行 / 阻塞 / 等待 / 终止。

异常

  • 死锁：检测并打破，记录受影响线程。
  • 栈溢出：终止线程并报告。
  • 优先级反转：通过优先级继承缓解。

FR-05 图形桌面环境

目的

提供主用户界面：桌面、任务栏、启动器、通知与控制中心，硬件加速合成。

布局

区域职责
桌面图标、壁纸、右键菜单
任务栏运行中窗口、开始菜单、托盘、时钟
启动器应用网格/搜索、最近使用
通知中心通知、勿扰、快速开关
控制中心显示、声音、网络、账户、更新、无障碍

处理规则

  • 合成器：硬件加速合成，支持透明、阴影、动画。
  • DPI 缩放、多显示器、夜间模式。
  • 无障碍：高对比、屏幕阅读器、放大镜、完整键盘导航。
  • 主题：明/暗、强调色，热切换。

结果与状态

一致且响应的 UI；合成器状态：硬件合成 / 软件回退。

异常

  • GPU 驱动失败：自动回退到软件渲染并提示用户。
  • 合成器崩溃：由监管内核重启合成器，窗口内容保留。

FR-06 内置网络浏览器

目的

提供开箱即用的网络浏览能力，支持现代 Web 标准与标签页级隔离。

布局

标签栏、地址栏、书签、历史、下载、扩展管理。

触发

用户打开浏览器 / 点击外部链接 / 系统内链接跳转。

处理规则

  • 引擎兼容：HTML5、CSS3、ES2023+、WebAssembly、WebGL/WebGPU。
  • 安全：站点隔离、每标签沙箱、仅 HTTPS 模式、钓鱼/恶意软件黑名单。
  • 下载保存到 Downloads 目录，可配置。
  • 可选云同步书签/历史（需登录账户）。

结果与状态

网页渲染完成；下载落盘；标签页状态：加载中 / 已加载 / 崩溃。

异常

  • 离线：使用缓存与离线模式，提示连接状态。
  • 标签页崩溃：进程隔离，仅重启该标签，其余不受影响。

FR-07 超级修复界面（核心）

目的

系统崩溃或启动失败时，进入图形化修复环境，按确定性流水线自动诊断并修复 ≥99% 的常见软件类故障，使系统恢复可启动状态。

触发条件

  • 连续 3 次启动失败。
  • 监管内核检测到个性内核不可恢复的恐慌。
  • 用户在启动菜单手动选择"超级修复"。

进入

从受保护的恢复分区加载一个独立的最小修复内核 + 图形 GUI（与主系统隔离），即使主系统镜像损坏也能进入。

布局

诊断进度屏 → 修复动作面板 → 结果报告 → 高级工具。

自动修复流水线

图 2 · 超级修复界面自动修复流水线

处理规则

  • 每一步自动执行；执行任何变更前先创建还原点。
  • 默认非破坏性；破坏性操作（如分区重建、镜像重写）需用户确认。
  • 修复日志记录每步前后状态，支持逐回滚。
  • 联网辅助：本地副本损坏时可从更新服务器拉取已知良好的驱动/文件。
  • 每步完成即验证；验证通过则跳过后续不必要的破坏性步骤。

99% 覆盖范围

覆盖（计入 99%）不覆盖（标记需人工）
引导损坏、系统文件损坏、坏驱动、服务依赖错乱、配置/注册损坏、恶意软件、磁盘逻辑错误硬盘物理损坏、内存硬件故障、用户数据级丢失、主板/电源硬件故障

状态

状态说明允许转移
Entered已进入修复环境→ Diagnosing
Diagnosing采集故障特征→ Repairing
Repairing按流水线执行→ Verifying
Verifying验证可启动性→ Complete
CompleteSuccess / Partial / Failed→ Reboot

结果

系统恢复可启动；结果报告列出已修复项；提供"重启回桌面"。

异常

  • 修复分区损坏：提示并提供联网重镜像。
  • 磁盘不可修复：提供数据抢救到外置介质建议，标记需人工。
  • 无网络且本地副本损坏：使用本地缓存兜底；若仍失败则进入高级工具人工处理。

高级工具（手动）

  • 命令提示符、系统还原点管理、镜像重装（保留用户数据）、驱动管理、磁盘分区管理、内存检测、事件日志查看器。
承诺：对覆盖范围内的常见软件类故障，超级修复界面无需用户具备技术知识即可完成自动修复，并在完成后直接重启回桌面。

06 共享规则与例外

规则定义
还原点策略在任何影响系统的变更前创建还原点；按保留策略滚动保留。
隔离原则每个个性内核与每个浏览器标签页均运行于独立沙箱。
日志持久化所有关键操作写入落盘到受保护分区的修复日志。
权限模型管理类操作需提权；修复环境拥有独立管理员凭据。
驱动签名仅加载签名驱动；加载失败回滚到上一良好版本。
通知时序故障与修复结果在完成或需用户决策时通知，不打断自动流程。
